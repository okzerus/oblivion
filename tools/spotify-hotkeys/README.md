# Spotify mouse hotkeys

Управляет десктопным клиентом Spotify на Windows через кнопки мыши,
без использования системных медиа-клавиш и OSD.

## Управление

| Действие                                   | Комбинация            |
|---------------------------------------------|------------------------|
| Play / Pause                                 | mouse5                 |
| Следующий трек                               | Shift + mouse5         |
| Предыдущий трек                              | Shift + mouse4         |
| Развернуть Spotify поверх всего / свернуть в трей, если уже в фокусе | Ctrl + Shift + mouse5 |
| Лайк / анлайк текущего трека                 | Ctrl + Shift + mouse4  |

mouse4/mouse5 — боковые кнопки мыши (x1/x2). Любой клик без нужного
модификатора (например, просто mouse4, или Ctrl+mouse4/mouse5 без Shift)
скрипт не трогает — он проходит как обычно (например, «назад»/«вперёд» в
браузере).

## Как это работает

- **Команды воспроизведения** (play/pause, next, previous) отправляются
  напрямую в окно Spotify через `WM_APPCOMMAND` (`SendMessageTimeout`), а не
  через системные медиаклавиши. Поэтому не появляется оверлей Windows и не
  затрагиваются другие проигрыватели (например, вкладка с YouTube).
- **Лайк** не имеет такого системного аналога — в Windows нет
  "medIA-клавиши" для избранного, поэтому эта команда идёт через Spotify Web
  API (см. ниже), а не через окно приложения напрямую.
- **Перехват кнопок мыши** сделан через низкоуровневый хук `WH_MOUSE_LL`
  (raw WinAPI через `ctypes`, без сторонних библиотек). Состояние Ctrl/Shift
  проверяется через `GetAsyncKeyState` в момент клика — отдельный хук
  клавиатуры не ставится, поэтому обычный ввод с клавиатуры никак не
  затрагивается.
- **Разворачивание поверх полноэкранной игры**: скрипт использует стандартный
  обход ограничения `SetForegroundWindow` (временное подключение через
  `AttachThreadInput` + кратковременный `HWND_TOPMOST`). Для окна в
  оконном/безрамочном полноэкранном режиме Spotify просто появится поверх.
  Для игр с эксклюзивным полноэкранным режимом DirectX сама Windows свернёт
  игру при переключении фокуса — это стандартное поведение системы, как при
  Alt+Tab, и обойти его без сворачивания игры невозможно в принципе.
- **Открытие из полностью скрытого в трей состояния** (когда иконки нет даже
  на панели задач) идёт не через прямой `ShowWindow`, а через повторный
  запуск `Spotify.exe` — см. "Исправленный баг" ниже.
- **"Закрытие" Spotify, когда он уже в фокусе**: скрипт посылает окну Spotify
  `WM_CLOSE` — то же самое сообщение, которое получает окно при нажатии на
  крестик. Чтобы это сворачивало в трей, а не закрывало программу полностью,
  в самом Spotify должна быть включена настройка **"Свернуть в трей при
  закрытии"** (Settings → Show desktop icon / Minimize to tray on close).
- **Запуск Spotify**: если окно не найдено, скрипт сначала проверяет, не
  запущен ли процесс `Spotify.exe` вообще (через `CreateToolhelp32Snapshot`,
  без сторонних библиотек) — если да, но окно ещё не создано (Spotify только
  стартует), повторный запуск не выполняется, чтобы не открыть вторую копию.
  Если процесса нет — запускается через `spotify:` URI, с резервным
  вариантом через `%APPDATA%\Spotify\Spotify.exe` (это и есть путь вида
  `C:\Users\<Вы>\AppData\Roaming\Spotify\Spotify.exe` — определяется
  автоматически через переменную окружения, привязывать к конкретному имени
  пользователя не нужно).

## Исправленные баги

### Замороженное окно после разворачивания из трея

Если Spotify был полностью скрыт в трей (без иконки на панели задач), и его
разворачивали напрямую через `ShowWindow` (в том числе через цикл
minimize → restore — первая попытка исправить это не сработала), окно
показывалось "живым", но фактически замороженным — ничего не анимировалось,
кнопки не нажимались. При обычном разворачивании из панели задач (когда
иконка там оставалась) такого не было.

Оказалось, что при повторном запуске `Spotify.exe`, пока он уже работает
(даже скрытый в трей), сам Spotify корректно активирует и показывает своё
существующее окно вместо запуска второй копии — это и есть его встроенный
механизм разворачивания, и он не ломает рендер, в отличие от прямых вызовов
`ShowWindow` снаружи. Теперь скрипт использует именно это: вместо
`ShowWindow` для скрытого окна он просто запускает `Spotify.exe` ещё раз и
ждёт, пока окно станет видимым, — дальше уже применяется обычное
принудительное разворачивание поверх всего (см. выше).

### Третье нажатие ничего не делало

После разворачивания из трея и последующего закрытия (второе нажатие) окно
Spotify пряталось, но Windows иногда продолжал считать его "в фокусе"
(`GetForegroundWindow` возвращал его хендл, хотя окно уже не видно) — из-за
этого третье нажатие снова уходило в ветку "закрыть", посылая `WM_CLOSE`
уже скрытому окну, то есть ничего не менялось. Исправлено проверкой
видимости окна (`IsWindowVisible`) перед тем, как считать его
сфокусированным: скрытое окно теперь всегда обрабатывается как "нужно
показать", независимо от того, что говорит `GetForegroundWindow`.

## Настройка лайка текущего трека

Программной "кнопки лайка" на уровне Windows не существует — в отличие от
play/pause/next/previous это не системная медиакоманда, а функциональность
только внутри самого приложения Spotify. Отправить искусственное нажатие
в скрытое окно ненадёжно (Chromium-приложения не гарантированно обрабатывают
синтетические сообщения клавиатуры для внутренних горячих клавиш). Поэтому
лайк/анлайк сделан через официальный **Spotify Web API** — тот же эффект,
что при нажатии на сердечко, но не через окно приложения, а через облако:
работает даже если окно спрятано, ничего не открывая и не разворачивая.

Настраивается один раз:

1. Зайти на https://developer.spotify.com/dashboard и создать приложение
   (имя и описание — любые, это личное приложение только для вас).
2. В настройках приложения добавить Redirect URI ровно такой:
   `http://127.0.0.1:8888/callback`
3. Скопировать **Client ID** приложения (Client Secret не нужен — используется
   PKCE-flow, без секрета).
4. Запустить один раз:
   ```
   python spotify_auth_setup.py
   ```
   Скрипт откроет браузер для входа/подтверждения доступа и сохранит
   refresh-токен в `%LOCALAPPDATA%\SpotifyHotkeys\api_credentials.json`.

Дальше `spotify_hotkeys.py` использует этот файл автоматически. Файл даёт
доступ к чтению текущего трека и изменению вашей библиотеки "Любимые
треки" — храните его так же, как пароль, никому не передавайте и не
коммитьте в git. Если Ctrl+Shift+mouse4 нажат до этой настройки, в лог
попадёт предупреждение и ничего больше не произойдёт.

### Если лайк не срабатывает

`spotify_hotkeys.py` результат лайка только логирует в файл — если
попробовать и "ничего не произошло", проще всего запустить
`python spotify_api.py` напрямую: он делает то же самое, но печатает
результат или полный текст ошибки сразу в консоль. Частые причины:

- **Скрипт `spotify_hotkeys.py` запущен ещё в старой версии.** Это фоновый
  процесс — обновление файлов на диске само по себе его не перезапускает.
  После любого обновления скрипта нужно завершить старый процесс
  (диспетчер задач → `pythonw.exe`/`python.exe`, либо просто перезайти в
  систему) и дать планировщику запустить его заново.
- Redirect URI в настройках приложения на Spotify Dashboard не совпадает
  посимвольно с `http://127.0.0.1:8888/callback` (частая ошибка — `localhost`
  вместо `127.0.0.1`, или лишний слэш).
- Ничего не играет в моменте (проверяется через Spotify Connect, поэтому
  не обязательно именно в этом окне — но играть должно хоть где-то).
- Доступ отозван на https://www.spotify.com/account/apps/ — тогда нужно
  заново запустить `spotify_auth_setup.py`.

## Требования

- Windows 10/11.
- Python 3.8+ — используется только стандартная библиотека (`ctypes`,
  `urllib`, `http.server`), никаких `pip install` не требуется.
- Интернет — нужен только для лайка (Spotify Web API); воспроизведение,
  разворачивание окна и запуск Spotify работают полностью локально.

## Запуск при старте Windows

Важный технический момент: низкоуровневый хук мыши работает только в рамках
интерактивной сессии рабочего стола, которой **не существует до входа в
систему**. Поэтому буквально "до логина" такой скрипт функционировать не
может — это ограничение самой Windows, а не скрипта. Ближайший к этому
моменту, с которого хук может реально начать работать, — это **вход
пользователя в систему**, и именно на него стоит настраивать автозапуск.

Планировщик заданий (Task Scheduler) с триггером **"При входе в систему"**
предпочтительнее папки автозагрузки: элементы автозагрузки Windows
специально придерживает на несколько секунд после входа (staggered startup),
а задания планировщика запускаются сразу, независимо от того, успели ли
стартовать другие программы — то есть именно то поведение, которое нужно.

Настройка:

1. Открыть **Планировщик заданий** → **Создать задачу** (не «простую задачу»,
   чтобы были доступны все параметры).
2. Вкладка **Общие**:
   - «Выполнять только для вошедших пользователей» (не «независимо от входа
     пользователя» — хуку ввода нужен рабочий стол).
   - Повышенные привилегии не нужны: Spotify всегда работает без
     администраторских прав, поэтому и скрипт не стоит запускать от админа.
3. Вкладка **Триггеры**: «При входе в систему» — «Пользователь: [ваша
   учётная запись]», без задержки.
4. Вкладка **Действия**: «Запуск программы»:
   - Программа: путь к `pythonw.exe` (без `w` откроется консольное окно) —
     например `C:\Users\<User>\AppData\Local\Programs\Python\Python3xx\pythonw.exe`.
   - Аргументы: `"C:\путь\к\spotify_hotkeys.py"`.
   - Рабочая папка: папка со скриптом (там же должен лежать `spotify_api.py`).
5. Вкладка **Параметры**: включить «Перезапускать через 1 минуту, до 3 раз»
   на случай сбоя — это единственное, что нужно для устойчивости к падениям,
   всё остальное скрипт обрабатывает сам (переживает отсутствие запущенного
   Spotify, ошибки при отправке сообщений и т.д.).

### Альтернатива без Python

Скрипт можно собрать в отдельный `.exe`, чтобы вообще не зависеть от
наличия Python в системе:

```
pip install pyinstaller
pyinstaller --onefile --noconsole spotify_hotkeys.py
```

(PyInstaller сам подхватит `spotify_api.py` рядом со скриптом.) Полученный
`dist\spotify_hotkeys.exe` указывается напрямую как «Программа» в действии
планировщика — шаги 1–5 выше не меняются, кроме самого пути.

## Логи

Скрипт пишет лог в `%LOCALAPPDATA%\SpotifyHotkeys\spotify_hotkeys.log`
(с ротацией) — туда стоит смотреть, если что-то не срабатывает: не найдено
окно Spotify, хук не установился, ошибка запроса к Web API и т.д.

## Известные ограничения

- Один запущенный экземпляр за раз (проверяется через именованный mutex) —
  повторный запуск просто тихо завершится.
- Если у Spotify когда-нибудь изменится класс главного окна
  (`SpotifyMainWindow`), скрипт подстрахован резервным поиском окна по имени
  процесса (`Spotify.exe`), но это стоит иметь в виду при странном поведении
  после обновления клиента.
- Лайк требует один раз настроенного доступа к Spotify Web API (см. выше) и
  интернета в момент нажатия.
- Скрипт не тестировался вживую в этой среде (linux-контейнер без Windows) —
  проверьте все комбинации (mouse5, shift+mouse4/5, ctrl+shift+mouse4/5,
  включая разворачивание поверх полноэкранной игры и восстановление из
  полностью скрытого в трей состояния) на реальной машине перед тем, как
  полагаться на автозапуск.
